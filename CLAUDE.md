# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

### Development
```bash
bun dev              # Vite + worker inline via @cloudflare/vite-plugin → http://localhost:5173
bun run dev:all:wsl  # Vite + Trigger.dev in parallel (WSL)
bun run dev:all:mac  # Vite + Trigger.dev in separate Terminal tabs (macOS)
bun cf:dev           # Wrangler standalone (--env local, port 8787) — needs dist/client, auto-created
```

### Quality
```bash
bun run type-check   # TypeScript check (tsc -b)
bun run check        # Biome lint + format
bun test:run         # Vitest
```

### Database
```bash
bun db:generate          # Generate Drizzle migrations from schema changes
bun db:migrate           # Apply migrations locally
bun db:migrate:staging   # Apply to staging D1
bun db:migrate:prod      # Apply to production D1
bun db:studio            # Drizzle Studio UI
bun db:seed:local        # Seed local database
bun db:seed:staging      # Seed staging D1 (uses wrangler remote)
bun db:reset             # Reset local database (wipe all data, keep schema)
```

### Build & Deploy
```bash
bun build                # TypeScript + Vite build
bun build:staging        # Staging build
bun build:production     # Production build
bun cf:deploy            # Deploy to production
bun cf:deploy:staging    # Deploy to staging
bun cf:check             # Type-check + build + dry-run deploy
```

### Other
```bash
bun stripe:listen        # Forward Stripe webhooks locally
bun trigger:dev          # Trigger.dev local dev
bun i18n:extract         # Extract new i18n keys
bun i18n:sync            # Sync translation files
```

## Architecture Overview

This is a fullstack SaaS boilerplate running entirely on **Cloudflare Workers** — no Node.js server.

### Request flow
```
Browser
  → Cloudflare Workers (src/server/index.ts — Hono app)
      → /api/auth/*      Better Auth (OAuth, email/password, sessions)
      → /trpc/*          tRPC router (dashboard mutations/queries)
      → /api/v1/*        REST endpoints (Stripe webhooks, public API)
      → /*               SPA fallback (serves React app from dist/client)
```

### Client (src/client/)
- **React 19** SPA with **TanStack Router** (file-based routing, auto code-splitting)
- Routes live in `src/client/routes/` — route groups `(auth)/` and `(protected)/` are layout wrappers
- `routeTree.gen.ts` is auto-generated by TanStack Router — never edit it manually
- **tRPC** via `@trpc/react-query` for all dashboard data (full type inference from server)
- **Better Auth** browser client at `src/client/lib/auth-client.ts`
- **i18next** for translations; locale JSON files in `src/client/locales/`; always add a fallback string as the second `t()` argument: `t("key", "English fallback")`
- Path alias `@client` → `src/client/`

### Server (src/server/)
- **Hono** HTTP framework, entry point: `src/server/index.ts`
- **tRPC** procedures in `src/server/lib/trpc.ts` — use `publicProcedure` or `protectedProcedure` (requires session)
- **tRPC routers** in `src/server/routers/trpc/`: `user`, `billing`, `invoices`, `nfse`, `apiKeys`, `settings`
- **REST routers** in `src/server/routers/rest/`: Stripe webhooks, Trigger.dev callbacks
- **Services** in `src/server/services/`: business logic (billing, email, NFSe, invoice PDF)
- **Better Auth** config at `src/server/lib/auth.ts`
- Path alias `@server` → `src/server/`

### Database (Drizzle + D1)
- SQLite via Cloudflare D1, accessed through Drizzle ORM
- Schema files in `src/server/db/schema/` — each domain has its own file
- `initDb(env)` in `src/server/db/index.ts` creates the Drizzle instance from the `env.DB` binding
- Migrations in `src/server/db/migrations/` — generated by `bun db:generate`, applied by `bun db:migrate`
- Local dev uses a `.wrangler/` SQLite file; staging/prod use D1 HTTP driver

### Infrastructure bindings (wrangler.jsonc)
| Binding | Purpose |
|---------|---------|
| `DB` | D1 SQLite database |
| `SESSION_KV` | Better Auth session storage |
| `CACHE_KV` | General-purpose cache |
| `STORAGE` | R2 bucket (invoices, NFSe XML, PDFs) |
| `EMAIL` | Cloudflare Email binding (transactional) |

### Background jobs (Trigger.dev)
- Tasks live in `trigger/` directory
- Call internal REST endpoints authenticated with `INTERNAL_API_KEY`
- Local dev: `bun trigger:dev`; deploy: `bun trigger:deploy`

### Environment variables
- **Server secrets**: `.dev.vars` locally; `wrangler secret put NAME` for staging/prod
- **Public server vars**: defined in `wrangler.jsonc` under `vars`
- **Client build-time vars**: prefixed `VITE_*`, baked into the browser bundle by Vite
- See `.env.staging.example` / `.env.production.example` for required secrets

### Two TypeScript compilation targets
- `tsconfig.app.json` — client (React, browser DOM, `@client` alias)
- `tsconfig.worker.json` — server (Cloudflare Workers types, `@server` alias)
- `bun run type-check` runs `tsc -b` which checks both

### Shared code
- `src/shared/` — types and utilities importable from both client and server
- Path alias `@shared` → `src/shared/`
